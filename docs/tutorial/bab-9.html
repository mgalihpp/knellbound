Performa dan Langkah Lanjut

Semua keputusan di Bab 1 dibuat demi performa. Bab ini menunjukkan cara mengukurnya sendiri, angka nyata dari setiap fase, batas pendekatan GDScript, dan ke mana proyek ini bisa dibawa berikutnya.

Cara mengukur

Konsep · ukur dulu, baru optimasi

Tebakan tentang apa yang lambat hampir selalu salah. Godot punya tiga alat yang cukup untuk proyek ini: Monitors (Debugger → Monitors: FPS, waktu proses, draw call, objek), Profiler (Debugger → Profiler → Start: waktu per fungsi GDScript, kolom Self = waktu di fungsi itu sendiri), dan Visual Profiler (waktu CPU/GPU per tahap render).

  1. Matikan vsync supaya FPS tidak terkunci di refresh rate monitor: Project Settings → Display → Window → V-Sync Mode = Disabled (atau sementara dari kode: DisplayServer.window_set_vsync_mode(DisplayServer.VSYNC_DISABLED)).
  2. Buat situasi berat yang bisa diulang: F5 (semua senjata maks), lalu F1 beberapa kali (+500 musuh). Panel debug HUD menampilkan FPS dan jumlah objek tiap jenis.
  3. Jalankan Profiler 10 detik di situasi itu. Urutkan menurut Self. Di proyek ini yang teratas selalu EnemySwarm.tick, _separate, upload, SpatialHash.build, ProjectileField.tick.
  4. Ubah satu hal, ukur lagi di situasi yang sama. Profiler GDScript menambah overhead; bandingkan angka FPS tanpa profiler untuk keputusan akhir.

Ke mana waktu frame pergi

Pada 1000+ musuh, hampir seluruh biaya ada di loop GDScript yang menyentuh setiap slot setiap frame:

  • EnemySwarm.tick: gerak per perilaku, satu akar kuadrat per musuh.
  • SpatialHash.build + _separate: tiga loop counting sort, lalu hingga 12 cek tetangga untuk setengah musuh per frame.
  • upload() semua Field: 9 penulisan float per instance. Di GDScript setiap penulisan indeks packed array adalah panggilan terpisah; ini biaya per instance terbesar.
  • ProjectileField.tick: satu query_circle per proyektil yang hidup.

Yang tidak mahal: Game (urutan), director, UI, SaveData, Audio. Semuanya bekerja per kejadian atau per frame, bukan per objek.

Kapan pindah ke C# atau GDExtension

Untuk target proyek ini (≈1000–1500 musuh di 60 FPS di PC desktop), GDScript atas packed array sudah cukup. Kalau kamu ingin 5000+ musuh, atau target perangkat lemah, rencana dari ARCHITECTURE.md adalah memindahkan hot path sambil mempertahankan API publik, sehingga Game, senjata, dan UI tidak berubah:

  1. EnemySwarm.tick + separasi + SpatialHash: loop ketat per slot, ideal untuk GDExtension C++ (atau C# dengan Span<T> atas array struct). Query menulis indeks ke buffer yang dipakai ulang, bukan membuat array baru.
  2. ProjectileField.tick: memakai hash yang sama tanpa melewati batas bahasa per proyektil.
  3. Upload buffer: isi PackedFloat32Array transform + custom di kode native, lalu tetap satu multimesh_set_buffer.
  4. C# atau GDExtension? C# bila tim lebih nyaman dan cukup dengan peningkatan 5–20×; GDExtension (C++/Rust) bila butuh SIMD atau multithread (WorkerThreadPool per sel grid).
Konsep · batas bahasa

Memanggil fungsi native dari GDScript punya biaya per panggilan. Pindahkan seluruh loop, bukan isi loop. swarm.tick(dt, target, shots) sebagai satu panggilan native yang memproses 4000 slot jauh lebih cepat daripada 4000 panggilan native_move(i) dari GDScript.

Alternatif lain sebelum menulis kode native: kurangi kerja. Separasi bisa dijalankan sepertiga musuh per frame (separation_stride = 3), musuh jauh di luar layar bisa di-tick dengan dt lebih besar setiap beberapa frame, dan relokasi bisa lebih agresif. Ukur dulu efek setiap perubahan.

Ide pengembangan lanjut

Setiap ide di bawah bisa dikerjakan dengan pola yang sudah kamu pelajari. Di kurung: bab yang paling relevan.

  • Peta kedua dengan tile tanah, dekorasi, dan WaveTable sendiri; pilih peta di layar pilih hunter (Bab 1, 5, 8).
  • Senjata ke-6 dan evolusinya: mis. cambuk yang menyapu setengah lingkaran di depan pemain memakai query_circle + cek sudut (Bab 3, 4).
  • Perilaku musuh baru: pengepung yang berputar di radius tetap, atau musuh yang meledak saat mati dan merusak musuh lain (Bab 5, 6).
  • Arcana / kartu modifier run: Resource yang mengubah aturan (semua proyektil memantul, gem memberi heal), dipilih di awal run (Bab 2, 8).
  • Achievement berbasis rekor di SaveData, dengan migrasi save v3 (Bab 8).
  • Lokalisasi: pindahkan teks UI ke file terjemahan Godot (tr()), mulai dari Bahasa Indonesia (Bab 7).
  • Sentuhan audio: musik yang naik intensitas saat boss muncul dengan crossfade dua lapis (Bab 8).
  • Build web: repo sudah punya preset Web (single-threaded, renderer Compatibility). Ekspor dan ukur ulang performa di browser (README).
  • Tes otomatis untuk logika murni: Leveling.add, Stats, DropTable.roll dengan seed tetap, SaveData._from_dict dengan file rusak.
