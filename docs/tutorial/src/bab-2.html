XP, Stats dan Level Up

Game jadi game ketika ada pilihan. Musuh mati menjatuhkan gem, gem memberi XP, XP memberi level, dan tiap level pemain memilih satu dari tiga upgrade. Di balik itu ada dua sistem yang dipakai sampai Fase 8: Stats dan pause.

TujuanGem biru/hijau/merah/ungu jatuh dari musuh, melompat kecil lalu tersedot ke pemain saat masuk radius magnet. Bar XP penuh → game berhenti, layar "LEVEL UP!" menampilkan 3–4 kartu (senjata atau relik), plus tombol Reroll/Skip/Banish. Bisa dimainkan dengan keyboard, mouse, dan gamepad.

GemField: pola yang sama, objek yang berbeda

Gem dibuat persis seperti musuh: packed array paralel, swap-with-last, satu MultiMesh, layout buffer 16 float yang sama, shader billboard yang sama. Itu keuntungan pola yang konsisten: kamu sudah tahu 80% kode pickups/gem_field.gd sebelum membacanya.

  1. Di main.tscn tambahkan Node3D GemField, tempel pickups/gem_field.gd, isi sheet = art/sprites/gems.png (baris = tier warna, kolom = frame kilau).
  2. Hubungkan sinyal kematian di Game._ready: swarm.enemy_died.connect(_on_enemy_died), lalu di handler panggil gems.drop(at, data.xp_value).
  3. Di Game._process setelah flush_dead(): var xp := gems.tick(dt, player.pos2, magnet).
Konsep · signal

Sinyal adalah cara node memberi tahu "sesuatu terjadi" tanpa tahu siapa yang mendengar. EnemySwarm mendeklarasikan signal enemy_died(position, data, flags) dan memanggil enemy_died.emit(...). Game yang menyambungkan sinyal itu ke fungsinya. Swarm tidak perlu tahu ada gem, efek, atau peti. Kalau besok kamu menambah sistem statistik, cukup sambungkan satu handler lagi.

  • dropDi atas max_gems (400), gem baru tidak dibuat; nilainya ditambahkan ke satu gem "bank" acak yang naik tier. Jumlah objek tetap terbatas walau 300 musuh mati per detik, dan pemain tetap mendapat semua XP-nya.
  • tickGem diam sampai l2 < magnet² (membandingkan kuadrat jarak, tanpa akar). Saat tertangkap ia diberi kecepatan menjauh (-d · pop_speed), lalu tiap frame dipercepat menuju pemain. Hasilnya lompatan kecil yang memuaskan sebelum tersedot.
  • overshootKalau langkah frame ini lebih panjang dari jarak tersisa (v.length() * dt >= dist), gem langsung dikoleksi. Tanpa ini gem cepat bisa melewati pemain dan berputar-putar.
  • whileLoop memakai while i < count dan tidak menaikkan i setelah menghapus, karena slot i sekarang berisi gem terakhir yang belum diproses.

Di upload(), indeks 7 (origin.y) diisi gelombang sinus kecil: gem mengambang naik turun tanpa satu baris kode animasi pun di sisi CPU selain angka itu.

Stats dan StatModifier

Begitu ada upgrade, pertanyaan desainnya: bagaimana "+10% damage" dari relik, "+10 max HP" dari karakter, dan "+15% damage" dari toko digabung tanpa saling menimpa? Jawaban proyek ini: satu rumus untuk semua stat.

Konsep · additive vs multiplicative

nilai = (base + Σflat) × (1 + Σpercent). Semua persen pada satu stat dijumlah dulu. Dua relik +10% = +20%, bukan 1,1 × 1,1 = +21%. Ini membuat tooltip mudah dihitung pemain dan mencegah stat meledak eksponensial saat ada puluhan sumber bonus. Karakter hanya mengubah base; semua yang lain adalah modifier.

  • enumStats.Id disimpan sebagai angka di file .tres (stat = 0 = MIGHT). Karena itu ada aturan: tambah id baru di akhir, jangan pernah mengurutkan ulang. Menyisipkan di tengah akan diam-diam mengubah arti semua file data.
  • _valueNilai akhir di-cache. value(id) hanya membaca array, jadi senjata boleh memanggilnya tiap frame. Hitung ulang terjadi hanya saat modifier ditambah.
  • timesadd_modifier(m, -1) membatalkan modifier; Fase 8 memakai times = level untuk upgrade toko.

Kurva XP

Kurvanya linear bertahap: +10 XP per level sampai level 20, +13 sampai 40, lalu +16. Level awal cepat (level 2 cukup 5 XP, satu-dua gerombolan), lalu melambat. add() memakai while, jadi satu gem bank berisi 2000 XP bisa memberi beberapa level sekaligus, dan fungsi itu mengembalikan jumlahnya. Game menyimpannya di antrian pending_levels.

Pause: process_mode

Konsep · SceneTree.paused dan process_mode

Saat get_tree().paused = true, Godot berhenti memanggil _process, _input, timer, dan tween pada node dengan process_mode = PAUSABLE. Mode default INHERIT mengikuti induk. Node dengan ALWAYS tetap jalan. Jadi layar level up (CanvasLayer) diberi process_mode = ALWAYS supaya bisa menerima input dan menjalankan tween pop-in walau dunia berhenti.

Game sendiri juga ALWAYS (ia perlu menerima tombol pause untuk unpause), lalu memeriksa sendiri di baris pertama _process:

Layar tidak dibuka di tengah frame. Level up dicatat (pending_levels += leveling.add(...)), lalu di akhir frame, setelah HUD diperbarui:

Kenapa antrian, bukan langsung? Karena satu gem bisa memberi tiga level, dan pemain harus memilih tiga kali. Dengan antrian, setiap pilihan cukup mengurangi satu dan menawarkan lagi; dunia baru jalan setelah antrian habis. Fase 4 menambahkan antrian kedua (pending_chests) dengan pola yang persis sama.

UpgradeOffer dan UpgradePool

Satu kartu = satu UpgradeOffer (RefCounted, bukan Resource: ia dibuat saat runtime dan dibuang setelah dipilih). Ia tahu jenisnya, item yang di-upgrade, level berikutnya, dan cara menerapkannya.

UpgradePool (Resource, data/upgrade_pool.tres) adalah daftar semua senjata dan relik yang bisa muncul. roll() mengumpulkan kandidat: level berikutnya dari item yang dimiliki, plus item baru selama slot (6 senjata, 6 relik) masih kosong, membuang yang di-banish, mengacak, lalu mengambil 3 (atau 4, peluang 10% × LUCK).

Layar sebagai "view"

Aturan yang dipegang sampai Fase 8: layar hanya menampilkan dan memancarkan sinyal. LevelUpScreen tidak tahu sisa reroll, tidak mengubah pemain, tidak meng-unpause. Ia emit picked(offer), reroll_requested, skip_requested, banish_requested(offer); Game yang memegang aturannya.

  1. Scene baru, root CanvasLayer LevelUpScreen (layer 10), process_mode = Always, tempel ui/level_up_screen.gd. Simpan ui/level_up_screen.tscn.
  2. Isi: CenterContainer (anchor Full Rect) → PanelContainer (%Panel) → VBoxContainer berisi Label judul, Label %Subtitle, VBoxContainer %Cards, HBoxContainer berisi tiga Button (%RerollButton, %SkipButton, %BanishButton).
  3. Klik kanan node → Access as Unique Name untuk node yang dipakai skrip. Di kode cukup %Panel, tidak perlu path panjang yang rusak saat struktur berubah.
  4. Kartu dibuat dari kode di _ready (maksimal 4 Button), lalu diisi ulang tiap present().
  5. Instance layar ini di main.tscn; sambungkan sinyalnya di Game._ready.

Detail input yang membuat layar terasa rapi: tombol angka 1–4 memilih kartu langsung; INPUT_GRACE_MS = 300 menelan tekanan tombol selama 0,3 detik setelah layar muncul (supaya Space yang masih ditekan dari gameplay tidak langsung memilih kartu); dan ui_accept diberi Joypad A di Input Map.

Checkpoint
  • Gem muncul di tempat musuh mati, terlihat melompat kecil sebelum tersedot.
  • Bar XP di atas layar terisi; saat penuh, semua musuh berhenti dan layar level up muncul. Tween pop-in tetap berjalan (bukti process_mode = ALWAYS).
  • Pilih Bloodied Blade: angka damage aura naik 10%. Tekan F4 (debug +1 level) beberapa kali dengan cepat: layar muncul berulang sampai antrian habis.
Kesalahan umum
  • Layar level up muncul tapi tidak bisa diklik / tween membeku. process_mode layar masih Inherit. Set ke Always di Inspector.
  • Game tidak bisa di-unpause. Node yang membaca tombol pause ikut berhenti. Game harus Always dan memeriksa pause sendiri.
  • Relik "tidak berefek". Senjata membaca data.damage langsung, bukan damage(). Cari dengan Search → Find in Files untuk data.damage.
  • File relik rusak setelah menambah stat. Id disisipkan di tengah enum; semua stat = n di .tres sekarang menunjuk stat lain.
