Knellbound dari Nol
Bab 0

Persiapan

Sebelum menulis kode game, siapkan proyek yang benar: struktur folder, pengaturan window, peta input, dan alat pembuat sprite. Kesalahan di sini (mis. filter tekstur) baru terasa jauh di belakang, jadi kerjakan dengan teliti.

TujuanProyek Godot kosong bernama Knellbound yang bisa dijalankan, dengan folder, Input Map, dan pengaturan render yang sama dengan repo, plus tools/gen_sprites.py yang bisa menulis PNG ke art/.

Install Godot 4.7 dan Python

  1. Unduh Godot 4.7.x (Standard, bukan .NET) dari godotengine.org/download. Proyek ini memakai GDScript saja. Di Windows, file Godot_v4.7.2-stable_win64.exe bisa langsung dijalankan; versi _console.exe berguna karena membuka jendela terminal yang menampilkan print() dan error.
  2. Install Python 3.10+ dari python.org, lalu Pillow (pustaka gambar) lewat terminal: pip install pillow. Hanya generator sprite yang butuh Pillow; tools/gen_audio.py cukup pustaka standar.
  3. Install git. Panduan ini sering meminta kamu membandingkan kode dengan commit fase.

Membuat proyek kosong

  1. Buka Godot. Di Project Manager klik + Create.
  2. Project Name: Knellbound. Pilih folder kosong. Renderer: Forward+ (proyek memakai shader spatial unshaded dan glow; Forward+ adalah renderer desktop default). Version control: Git.
  3. Klik Create & Edit. Godot membuat project.godot, icon.svg, dan folder tersembunyi .godot/ (cache impor, jangan di-commit).
Konsep · project.godotSemua yang kamu atur di Project → Project Settings disimpan sebagai teks di project.godot. Itu sebabnya repo bisa menunjukkan pengaturan persisnya, dan diff git memperlihatkan kapan sebuah pengaturan berubah. Mengeditnya dengan tangan boleh, tapi lebih aman lewat editor.

Struktur folder

Buat folder berikut di panel FileSystem (klik kanan res:// → Create New → Folder). Tidak semua langsung terisi; yang penting kamu tahu di mana tiap jenis file tinggal.

res:// ├─ art/ sprites/ tiles/ icons/ ui/ ← ditulis oleh tools/gen_sprites.py ├─ audio/ sfx/ bgm/ ← ditulis oleh tools/gen_audio.py (Fase 8) ├─ autoload/ singleton global (Fase 7–8) ├─ characters/ character_data.gd ├─ core/ game.gd, spatial_hash.gd, camera_rig.gd, stats.gd, … ├─ data/ semua konten .tres: characters/ enemies/ weapons/ passives/ waves/ … ├─ enemies/ enemy_swarm.gd, spawn_director.gd, … ├─ fx/ pickups/ passives/ meta/ world/ ├─ player/ player.gd, player.tscn ├─ scenes/ main.tscn (run), nanti title.tscn, character_select.tscn, shop.tscn ├─ shaders/ sprite_billboard.gdshader, blob_shadow.gdshader, aura.gdshader, … ├─ tools/ gen_sprites.py, gen_audio.py, .gdignore ├─ ui/ hud, layar level up, tema └─ weapons/ weapon.gd, projectile_field.gd, aura/ knives/ orbit/ vial/ cross/

Aturannya: skrip dikelompokkan menurut fitur (enemies/, weapons/), sedangkan data konten (.tres) dikumpulkan di data/. Desainer bisa menyeimbangkan game hanya dengan membuka data/ di Inspector.

Konsep · .gdignoreFile kosong bernama .gdignore membuat Godot mengabaikan folder itu: tidak diimpor, tidak muncul di FileSystem. Folder tools/ berisi skrip Python, jadi diberi .gdignore. Panduan ini sendiri (docs/tutorial/) juga punya .gdignore supaya gambar WebP-nya tidak diimpor sebagai tekstur.

Pengaturan proyek

Buka Project → Project Settings. Aktifkan Advanced Settings (toggle kanan atas) supaya semua opsi tampil.

Window dan stretch

  1. Display → Window → Size: Viewport Width 1280, Height 720.
  2. Display → Window → Stretch: Mode canvas_items, Aspect expand.

canvas_items berarti UI dirancang di 1280×720 lalu diskalakan ke ukuran jendela sebenarnya; expand berarti layar yang lebih lebar menampilkan area lebih banyak, bukan bilah hitam. Dunia 3D tidak terpengaruh stretch karena ukurannya diatur oleh kamera orthographic (Bab 1).

Filter tekstur nearest

Rendering → Textures → Canvas Textures → Default Texture Filter = Nearest. Tanpa ini, ikon UI pixel art jadi buram karena diinterpolasi linear. Pengaturan ini hanya berlaku untuk node 2D/UI. Di 3D, filter diatur per material: Sprite3D.texture_filter = Nearest dan di shader uniform sampler2D sheet : filter_nearest. Kamu akan melihat keduanya di Bab 1.

Input Map

Game tidak pernah membaca tombol keyboard secara langsung. Ia membaca aksi bernama, dan Input Map memetakan tombol, stik, dan d-pad ke aksi itu. Pemain dengan gamepad dan keyboard jalan dengan kode yang sama.

  1. Buka tab Input Map. Ketik move_left di kolom Add New Action, tekan Add.
  2. Klik ikon + di baris aksi, tekan tombol A. Ulangi untuk ←, lalu tambahkan Joypad Axis 0 − (stik kiri ke kiri) dan Joypad Button 13 (d-pad kiri).
  3. Ulangi untuk move_right (D, →, Axis 0 +, Button 14), move_up (W, ↑, Axis 1 −, Button 11), move_down (S, ↓, Axis 1 +, Button 12). Set Deadzone keempatnya ke 0.2.
  4. Tambahkan pause (Esc, P, Joypad Start) dan restart (R, Joypad Back/Select).
  5. Aktifkan Show Built-in Actions, cari ui_accept, tambahkan Joypad Button 0 (A). Untuk ui_cancel tambahkan Joypad Button 1 (B). Default Godot tidak punya keduanya; Fase 2 dan 7 membutuhkannya.

Saat membuat aksi, pilih Physical Keycode untuk WASD. Dengan physical keycode, posisi tombol yang dihitung, jadi pemain dengan layout AZERTY tetap memakai tombol di posisi W-A-S-D. Di project.godot ini terlihat sebagai "physical_keycode":65 (A).

Membacanya di kode cukup satu baris, dari player/player.gd:

player/player.gd · baris 105–107
105func tick(dt: float) -> void:
106    var input := Input.get_vector(&"move_left", &"move_right", &"move_up", &"move_down")
107    pos2 += input * stats.value(Stats.Id.MOVE_SPEED) * dt

Input.get_vector mengembalikan Vector2 dengan panjang maksimal 1 dan sudah menerapkan deadzone, jadi gerak diagonal tidak lebih cepat dari gerak lurus.

Pengaturan lain di repo

  • Physics → 3D → Physics Engine = Jolt Physics (default baru Godot). Proyek ini tidak memakai fisika sama sekali; tabrakan dihitung sendiri (Bab 1).
  • rendering_device/driver.windows="d3d12": driver Direct3D 12 di Windows. Tidak wajib; Vulkan juga jalan.
  • GUI → Theme → Custom diisi res://ui/theme/game_theme.tres di Fase 7.

Fungsi render() mengubah baris ASCII menjadi gambar. Perhatikan dua aturan: huruf besar diberi bayangan otomatis (lebih terang di tepi atas/kiri, lebih gelap di tepi bawah), dan piksel kosong yang bersebelahan dengan piksel berwarna menjadi OUTLINE.

tools/gen_sprites.py · baris 94–139
 94def render(rows, w=16, h=16, pal=None, flat=""):
 95    """ASCII rows -> RGBA image ((w+2) x (h+2)) with shading + outline.
 96    `pal` adds/overrides palette entries for this sprite only; `flat` lists
 97    extra characters that are not auto-shaded."""
 98    colors = PAL if pal is None else {**PAL, **pal}
 99    flats = FLAT | set(flat)
100    cw, ch_ = w + 2, h + 2
101    img = Image.new("RGBA", (cw, ch_), (0, 0, 0, 0))
102    px = img.load()
103    grid = [[None] * w for _ in range(h)]
104    pad_top = h - len(rows)  # bottom-align so feet sit on the cell bottom
105    assert pad_top >= 0, "sprite taller than %d rows" % h
106    for y, row in enumerate(rows):
107        for x, ch in enumerate(row[:w]):
108            if ch != "." and ch != " ":
109                grid[y + pad_top][x] = ch
110
111    def solid(x, y):
112        return 0 <= x < w and 0 <= y < h and grid[y][x] is not None
113
114    for y in range(h):
115        for x in range(w):
116            ch = grid[y][x]
117            if ch is None:
118                continue
119            c = colors[ch]
120            if ch not in flats:
121                up = solid(x, y - 1) and grid[y - 1][x] == ch
122                down = solid(x, y + 1) and grid[y + 1][x] == ch
123                left = solid(x - 1, y) and grid[y][x - 1] == ch
124                if not up or not left:
125                    c = shade(c, 1.22)
126                elif not down:
127                    c = shade(c, 0.72)
128            px[x + 1, y + 1] = c
129    # outline
130    for y in range(ch_):
131        for x in range(cw):
132            if px[x, y][3] != 0:
133                continue
134            for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
135                nx, ny = x + dx, y + dy
136                if 0 <= nx < cw and 0 <= ny < ch_ and px[nx, ny][3] != 0 and px[nx, ny] != OUTLINE:
137                    px[x, y] = OUTLINE
138                    break
139    return img

Warna OUTLINE = (24, 16, 30) sengaja unik. Shader elite di Fase 5 mengenali piksel outline dengan membandingkan warna ini, lalu membuatnya menyala merah. Jadi skrip art dan shader punya "kontrak" lewat satu konstanta warna.

  1. Salin tools/gen_sprites.py dari repo (atau mulai dari versi Fase 1: git show 3f048ff:tools/gen_sprites.py, 438 baris; versi akhir 2720 baris).
  2. Buat tools/.gdignore kosong.
  3. Dari root proyek jalankan python tools/gen_sprites.py. Kembali ke Godot: editor mengimpor PNG baru otomatis.
CheckpointDi FileSystem muncul art/sprites/player_hunter.png (4 frame jalan, sel 18×18) dan art/sprites/enemies.png. Klik dua kali: gambarnya kecil dan tajam. Kalau buram di preview, itu hanya preview; yang penting filter di material nanti.

Kenapa sel 18×18?

Art digambar 16×16 piksel, ditambah 1 piksel outline di setiap sisi = 18. Skala dunia: 16 piksel = 1 unit dunia, jadi satu sel sprite di dunia berukuran 18 / 16 = 1.125 unit. Konstanta itu muncul di kode sebagai CELL_WORLD := 18.0 / 16.0. Sprite besar (boss) memakai sel 34 (32 + outline).

Plugin godot_ai (opsional)

Repo ini dibangun dengan bantuan plugin addons/godot_ai, jembatan MCP yang memungkinkan asisten AI menjalankan game, mengambil screenshot, dan mengirim input. Plugin ini bukan bagian dari game: tidak ada kode game yang memanggilnya, dan di HEAD folder addons/ ada di .gitignore. Kamu bisa mengabaikannya sepenuhnya. Kalau project.godot-mu berisi baris _mcp_game_helper=… di [autoload] tapi foldernya tidak ada, hapus baris itu dan baris [editor_plugins] supaya tidak muncul error.

Kesalahan umum
  • Sprite buram atau ada garis di tepi frame. Filter linear. Cek texture_filter di Sprite3D dan filter_nearest di shader. Garis tipis di tepi biasanya berasal dari mipmap; matikan mipmap di tab Import untuk sheet sprite.
  • Aksi tidak bereaksi. Nama aksi di kode harus sama persis (&"move_left"). Salah ketik tidak menimbulkan error kompilasi, hanya peringatan di Output saat dijalankan.
  • Python tidak menemukan PIL. pip menginstall ke Python lain. Pakai python -m pip install pillow.
LatihanTambahkan aksi dash (Space, Joypad Button 2) di Input Map, lalu buka project.godot di editor teks dan temukan bentuk teksnya. Hapus lagi sesudahnya; game tidak memakainya.
